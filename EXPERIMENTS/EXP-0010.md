# EXP-0010 — Standalone tools and on-demand queue

## Goal

Separate reusable operations from the binary core and allow a higher-level organ to request only the tools required for a task.

## Added tools

- `compression_tool`: compact binary temporal memory and restore it;
- `derived_views`: derive history, relation, matrix and graph from compact memory;
- `comparator`: compare derived structures with formal models;
- `tool_queue`: map declared needs to available tools and create an ordered work queue.

## Architecture

```text
organ / task
      ↓
required capabilities
      ↓
tool queue
      ↓
selected tools
      ↓
compact canonical memory
      ↓
derived views only when needed
      ↓
result
```

## Principle

Do not store every representation permanently. Keep a canonical compact state and instantiate derived views on demand.

## Boundary

The queue is intentionally simple. It does not yet execute arbitrary tools, resolve dependencies, estimate resource cost, or prove optimal scheduling. Those are later experiments.
