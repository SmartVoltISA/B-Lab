# EXP-0012 — Measured structural compression benchmark

## Confirmed results

CI Run #51 executed the benchmark on Ubuntu 24.04 with 10,000-symbol binary datasets.

### Structural bit-packing

For all four datasets:
- raw representation: 10,000 bytes (one byte per logical symbol);
- packed structural representation: 1,250 bytes;
- with 4 bytes of logical-length metadata: 1,254 bytes;
- exact round-trip tests pass.

This is an 8x reduction versus the benchmark's byte-per-symbol raw representation before metadata, and about 87.46% size reduction including the 4-byte length field.

### Structural representation followed by generic codecs

Measured compressed bytes (raw → structural):

- gzip: 45→30, 46→33, 54→30, 45→31
- bzip2: 42→45, 53→48, 46→45, 42→45
- xz: 112→80, 112→80, 116→80, 112→80
- lz4: 70→34, 73→39, 76→34, 70→34
- zstd: 23→21, 26→25, 28→21, 23→21
- brotli: 14→11, 19→15, 15→11, 14→11

Dataset order: alternating, zero_run, mixed, randomish.

## Verified interpretation

The current tool works as a lossless binary structural representation and bit-packed serializer. On this benchmark corpus, structural preprocessing improved the final compressed size for gzip, xz, lz4, zstd, and brotli on every tested dataset. bzip2 improved on zero_run and mixed but was worse on alternating and randomish.

The benchmark intentionally uses a byte-per-symbol raw baseline. Therefore the measured 8x structural reduction must not be presented as an 8x advantage over an already bit-packed binary representation; that comparison is a separate control for the next experiment.

## EXP-0012 extension — canonical three-tier memory

The same principle is now extended from a serializer into a memory architecture:

```text
canonical data
     ↓
minimal lossless encoding
     ↓
ACTIVE / TEMPORARY / LONG_TERM
     ↓
materialize only when requested
```

`TOOLS/memory_engine.py` implements:
- binary bit packing;
- deterministic byte RLE;
- raw fallback;
- persistent tier metadata;
- exact serialize/load reconstruction;
- UTF-8 text round-trip.

The engine never claims compression when the available transform is larger than raw storage. It therefore measures actual stored bytes rather than assuming a universal compression factor.
